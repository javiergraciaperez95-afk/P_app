PARA DEJAR SUPABASE LISTO (CUENTAS AL ESTILO MULLVAD)
=====================================================
Escrito el 18 de octubre de 2026. Proyecto: https://iuniglsiqnfvnotmfgdo.supabase.co

Cómo funciona ahora: cada móvil recibe un número de cuenta de 16 cifras, sin pedir nada. Su progreso se
guarda en Supabase con ese número. Con el número se entra desde otro móvil. Si la cuenta no tiene correo y
no se usa en 7 días, se borra sola. Con un correo unido (verificado con un código de 6 cifras) ya no caduca
y el número se puede recuperar con el correo. Los archivos antiguos (supabase-todas.sql y
supabase-app-unica.sql) eran del sistema anterior con cuentas de correo y contraseña: ya no se usan.


1. EJECUTAR EL SQL  (obligatorio, 1 minuto)
-------------------------------------------
Archivo: paglot-cuentas.sql (en esta carpeta).

  Supabase → el proyecto → SQL Editor → New query → pegar TODO el archivo → Run.

Sin esto la app funciona, pero el Perfil dice «La nube no responde» y el progreso solo se guarda en el móvil.


2. QUE EL CORREO LLEVE UN CÓDIGO  (para la parte del correo, 2 minutos)
-----------------------------------------------------------------------
La app pide un código de 6 cifras, no un enlace. Hay que ponerlo en la plantilla del correo:

  Supabase → Authentication → Emails (Email Templates) → «Magic Link»
  Cambiar el texto por algo así:

    <h2>Tu código de Paglot</h2>
    <p>Escribe este código en la app: <strong>{{ .Token }}</strong></p>

  (y lo mismo en la plantilla «Confirm signup», que es la que llega la primera vez).

Comprueba también que en Authentication → Providers → Email esté activado «Email».
Ojo: el servidor de correo gratuito de Supabase manda muy pocos correos por hora. Para muchos usuarios
habrá que poner un SMTP propio (Authentication → Emails → SMTP Settings).


3. NADA MÁS
-----------
El borrado de las cuentas anónimas de más de 7 días lo hace la propia base de datos cada vez que alguien
abre la app; no hace falta programar nada.
