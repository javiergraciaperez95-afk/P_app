RESUMEN DE LA CONVERSACIÓN

Tema principal
-------------
Hemos hablado sobre cómo automatizar Codex para revisar una gran cantidad de archivos mientras el usuario está ausente.

Objetivo inicial
----------------
El objetivo era poder enviar aproximadamente 300 instrucciones consecutivas a un chat de Codex, por ejemplo:

- Revisar archivo 1.
- Revisar archivo 2.
- Revisar archivo 3.

Conclusiones sobre la automatización
-------------------------------------
Se explicó que Codex no está pensado principalmente como una cola de cientos de mensajes independientes enviados automáticamente al mismo chat visual.

Las alternativas consideradas fueron:

1. Enviar una única instrucción amplia para que Codex recorra todos los archivos de forma secuencial.
2. Usar una automatización de Codex para mantener un objetivo o ejecutar trabajo recurrente.
3. Crear un script externo con Codex CLI, Agents SDK o la API para procesar una lista de archivos, registrar el progreso y reintentar errores.
4. Automatizar la interfaz de usuario, aunque se indicó que esta opción es frágil porque puede fallar por cambios de interfaz, tiempos de espera, límites o solicitudes de aprobación.

También se indicó que Codex Cloud puede continuar ejecutando tareas aunque el ordenador esté dormido, siempre que el entorno esté correctamente preparado y publicado.

Primera propuesta de prompt
---------------------------
Se propuso pedir a Codex que revisara los archivos indicados en:

C:\Users\javie\Downloads\Learning_language_app-main\Learning_language_app-main\Notas_archivos_noafectaalcodigo\review-list-English.txt

La revisión debía hacerse en orden, archivo por archivo, corrigiendo los problemas, ejecutando pruebas, registrando el progreso y generando un resumen final.

Problema detectado en esa propuesta
------------------------------------
Se detectó que no era conveniente usar el propio archivo review-list-English.txt para registrar el progreso, porque la lista original podría modificarse mientras se recorre.

También se detectó una contradicción: primero se indicaba que no se debía modificar ningún archivo dentro de Notas_archivos_noafectaalcodigo, pero después se pedía crear el resumen dentro de esa carpeta.

Prompt corregido
----------------
Se preparó un prompt más seguro con estas reglas:

- Leer la lista completa y respetar exactamente su orden.
- No modificar review-list-English.txt.
- Revisar y verificar cada archivo antes de pasar al siguiente.
- Corregir errores claros y verificables.
- Ejecutar las pruebas y comprobaciones adecuadas.
- Registrar el progreso en review-progress.md, fuera de la carpeta de notas.
- Registrar para cada archivo su estado, problemas, cambios, pruebas y bloqueos.
- Continuar con el siguiente archivo si uno falla.
- Reintentar los archivos fallidos al terminar la primera pasada.
- Si se alcanza un límite de ejecución, dejar anotados el último archivo completado y el siguiente pendiente.
- Crear el resumen final en:
  Notas_archivos_noafectaalcodigo\reviews\summary.md
- No modificar otros archivos de Notas_archivos_noafectaalcodigo.

Revisión de contenido de las lecciones
--------------------------------------
Se añadió que, además del código, Codex debe revisar las lecciones y los archivos de contenido para comprobar que:

- El contenido sea coherente y comprensible.
- Las traducciones tengan sentido.
- No falten campos, ejercicios o datos.
- Los ejercicios sean resolubles.
- No haya contradicciones entre lecciones o con la aplicación.
- Se mantenga la intención pedagógica original.

También se indicó que las mejoras que requieran decisiones de diseño, puedan cambiar el comportamiento esperado o no estén suficientemente claras deben documentarse sin aplicarse automáticamente.

Versión de estilo solicitada
----------------------------
El usuario pidió evitar un tono excesivamente formal o fórmulas de cortesía propias de otras variantes del español. Se acordó usar un español más directo y natural para España, con instrucciones en segunda persona cuando corresponda.
